# 可选 AI：模型配置与 RedReply 调用

本期为文字 AI：多套 Chat Completions 兼容模型配置、异步任务、短期上下文与 GUI。默认关闭，不自动接管普通微信消息。现有电影、游戏、点歌、图片、语音、转发和撤回继续走原有路径。Vision、ASR、TTS 生成、长期记忆和联网工具不在本期。

## 最短使用流程

1. 在新版 GUI 打开“AI 模型”，添加模型，填写 Base URL、模型 ID 和 API Key，勾选启用。
2. 点击“保存并测试模型”。测试为真实模型调用，会产生供应商用量；测试结果显示在下方任务列表，不发送微信，也不进入上下文。测试不要求启动监听。
3. 在 RedReply 将本目录的 `wechat-ai-script.json` 作为**新的独立插件**导入；或者把 `wechat-ai.redlang` 的命令定义放入自己的微信插件初始化代码。不要覆盖已有插件。不同 RedReply 版本的导入入口有所不同；JSON 是 script.json 数组格式，不是另一个 RedReply 程序。
4. 保持原 OneBot 地址、Token 和机器人 ID，启动监听。在白名单私聊/群聊发送 `AI 你好`。只有 `AI `（大写 AI 加一个空格）前缀触发示例。`AI清空上下文` 仅清理当前会话中该发送者的短期上下文。

示例每2秒查询一次任务，最多等待190秒；单次 OneBot 调用立即完成，不把模型请求塞进同步调用。示例在响应前检查本工具的能力扩展；QQ/TG 等其他接入不会调用本工具的 AI。启用 AI 之前已收到的旧消息没有来源登记，请用新消息触发。

默认提供 DeepSeek、阿里百炼、Ollama 和自定义兼容配置，模型 ID 由用户按实际权限填写。地址会自动追加 `/chat/completions`，也接受完整端点；不会猜测其他服务商或静默切换模型。百炼的地域、业务空间与 Key 需匹配。接口依据：[DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/)、[百炼](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[Ollama](https://github.com/ollama/ollama/blob/main/docs/api/openai-compatibility.mdx)。预设不是这些在线服务的运行保证。

## OneBot 扩展动作

以下动作是本工具扩展，**不是 OneBot11 标准动作**。它们共用现有鉴权连接，不开第二个 OneBot 客户端或额外公网端口。标准响应的 `echo`、`status`、`retcode` 保持原义。

### 1. 提交

```json
{
  "action": "submit_ai_task",
  "params": {
    "source_message_id": "本次入站消息ID",
    "user_id": "本次入站发送者ID",
    "group_id": "群聊时填入站群ID，私聊省略或填0",
    "text": "交给模型的文字",
    "profile_id": "可选，默认使用GUI当前配置",
    "request_id": "可选，默认使用来源消息ID作为幂等键"
  },
  "echo": "由调用者设置"
}
```

返回 `data.task_id` 与 `data.status=queued`。来源必须是当前已核对账号在24小时内真实发布的消息，并匹配发送成员、私聊/群聊与白名单。用户输入通过 JSON 对象序列化，不能直接拼进 JSON 字符串。

同一账号、相同 request_id 与相同请求重复提交，返回原任务；同一键用于不同文字/模型配置会失败。显式重新生成时请提供新的 request_id；不会自动重试可能已计费的请求。

### 2. 查询与取消

```json
{"action":"get_ai_task","params":{"task_id":"ai-..."}}
{"action":"cancel_ai_task","params":{"task_id":"ai-..."}}
```

任务状态：

| 状态 | 含义 |
| --- | --- |
| queued | 已持久化，等待配额及同会话前序任务 |
| running | 模型调用中 |
| generated | 已生成，`data.text` 可取；尚未发送微信 |
| awaiting_delivery | RedReply 已提交发送，等待微信真实回执 |
| delivered | 整条输出已确认发送，才提交上下文 |
| uncertain | 模型调用中断或微信发送待核对；未自动重试 |
| failed / cancelled / expired | 明确失败、取消或超过期限 |

GUI 测试的 `generated` 显示“测试完成”，不意味着微信送达。供应商 usage 未返回时显示缺失，不编造0用量。取消只适用于 queued/running/generated；已经入发送队列的输出，应在发送队列取消/撤回。取消 HTTP 请求不能撤销已经发生的供应商用量。

### 3. 显式发送

```json
{"action":"send_ai_task","params":{"task_id":"ai-..."}}
```

使用任务原始账号、白名单目标与完整生成文字，返回标准 `data.message_id` 输出回执。重复调用同一任务只返回已有输出，覆盖跨重启及两套数据库提交之间中断的情况。结果按文字发送，模型返回的 CQ 代码不会提升成图片、文件或操作。

`task_id`、来源消息 ID 和实际发送 `message_id` 互不替代。需要撤回时，对返回的输出回执调用现有 `delete_msg` / `schedule_delete_msg`；AI 文本自行声称“30秒后撤回”不会创建撤回计划。未确认送达的回答不会进入上下文。

此动作要求启用原有持久化发送队列。不发送部分模型流或推理过程，不执行模型工具调用，不把残缺、空回答或仅 reasoning 内容当作完整回答。

### 4. 清理上下文

```json
{"action":"clear_ai_context","params":{"source_message_id":"入站消息ID","user_id":"发送者ID","group_id":"群ID或0"}}
```

作用于该来源账号、会话与发送成员。GUI 可按会话成员或全部清理。清理会取消未提交的旧任务并增加上下文修订号；清理前已经排队发送的结果即使迟到，也不会重新写回被清理的上下文。此动作不撤回已有微信消息。

## 调度、上下文与限额

- 模型工作使用独立运行时与 `data/ai.sqlite3`，不占用微信原生操作线程；同一成员会话按序，跨会话有界并发。生成结果在发送或取消前会暂时阻挡同会话下一任务，最多保留5分钟领取窗口。
- 短期上下文按机器人真实 wxid、会话真实 wxid、发送成员真实 wxid 和模型配置 ID 隔离；改昵称不会串到其他人。群内默认每个成员独立，不擅自向模型外发全群历史。只保留经 AI 处理且已确认送达的问答，普通插件对话和模型测试不混入。
- 轮数、有效期和保守输入预算共同限制历史；只裁掉旧的完整问答对，不截断用户当前问题。输入预算使用 UTF-8 字节与消息开销的保守估算，不是供应商精确 tokenizer；过长新输入明确失败。
- 整轮期限包含排队和请求，默认90秒，可设5–180秒。尚未开始的任务可跨重启保留，但不会跨越原期限无限执行；中断的已开始调用标为待核对，不自动再次计费。
- 请求频率、并发与日 token 预留预算在 GUI 测试和聊天间共享。日预算按“输入预算＋输出上限”预留、UTC零点重置，0表示不设置日限额；这是保守配额，不是账单金额保证。供应商自己的限额仍有效。
- 全部队列最多1000个未完成任务，达到上限明确拒绝，不删除最旧任务。任务历史保留至少最近2000项和最近一天；过期来源、上下文定期清理。上下文有效期限制实际请求的历史范围。
- 没有跨供应商自动故障转移。修改/删除模型配置、关闭 AI、移除白名单或账号变化，会停止相关未提交工作。模型调用取消/超时后的用量可能无法判断。

## 密钥、迁移和日志

非敏感设置位于原 `config.json` 的 `ai` 字段；Key 独立保存在 `data/ai-keys.json`。Key 为便携本地文件，**不是加密保险箱**；随 data 迁移时需要自行保管。GUI 只返回 has_key，不返回已存 Key；留空保留，删除密钥需显式操作。普通导出、诊断和发布包不应携带 data 或 Key 文件。

普通协议日志省略 AI 提交正文和模型原始生成结果，结构化保存任务状态、独立 usage 与失败类型；不记录 API Key、供应商错误原文或含 Key 的 URL。用户需要的现有微信本地对话/已发消息日志继续保留。GUI 的 AI 任务页可以查看本机持久化生成结果。

仅允许 HTTP(S) 模型地址，禁止 URL 用户名、密码和查询参数；HTTP 需明确允许本地/内网明文连接。模型请求不跟随重定向，也不在失败后换地址重发 Key。远程模型请优先使用 HTTPS。

本期未修改系统剪贴板，不模拟全局键鼠，不激活微信窗口。发送仍经原有离屏/原生后端；AI 自身不调用 UIA、录音快捷键、虚拟声卡或窗口切换。
