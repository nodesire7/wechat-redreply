# RedLang → OneBot11 → 微信

兼容层位于 `src/compat.rs`。它处理平台动作和消息段，不按“查电影”“点歌”等插件名改写业务，也不修改 RedReply 的 QQ、TG 或 KOOK 接入。

| RedLang 操作 / 输出 | 接口动作 | 微信行为 |
| --- | --- | --- |
| `输出流` / 脚本回复 | `send_private_msg`、`send_group_msg`、`send_msg` | 按明确的目标 ID 与白名单路由；文字、图片分开发送，同次输出共用一个回执 |
| `图片` / CQ 图片 | `image` 段 | 支持 HTTP(S)、base64；微信出现真实服务器消息编号后确认 |
| `艾特` | `at` 段 | 显示可读姓名，当前不冒充原生艾特 |
| 引用来源 | `reply` 段 | 用于追踪来源；当前不冒充微信原生引用 |
| 合并转发 / `node` | 三种 `send_*forward_msg` 动作、普通输出内的 node | 转为本账号自聊中转，再生成原生 type19 合并卡；文字/图片前后顺序保留，缺失目标不猜测 |
| 点歌 custom / QQ JSON | `music`、受支持的 `json` / `xml` | 按本次曲目信息新建原生 type3 音乐卡；不换成同 ID 的旧曲缓存 |
| `语音` / CQ record | `record` 段 | 转码为 SILK 后调用原生 CGI127，显示真正语音气泡；不发送文件代替。目前限微信4.2.0.12 |
| `撤回@输出回执` | `delete_msg` | 只撤回此输出的全部实际拆分消息，不扩散到同一触发的其他输出 |
| 延时撤回扩展 | `schedule_delete_msg` | 在发送前也可登记；从实际发送后计时，最长 120 秒，预留逐条执行时间 |
| 好友 / 群 / 成员信息 | `get_friend_list`、`get_group_list`、`get_group_info`、`get_group_member_*`、`get_stranger_info` | 返回白名单会话或实际已观察成员；不伪造管理员权限 |
| 能力探测 | `get_capabilities`、`can_send_image`、`can_send_record` | 明确返回支持范围；语音还检查绑定机器的原生版本后端 |

`auto_escape=true` 保留 CQ 字面内容。其他普通文本或文本段中的 CQ 码统一展开；转发还接受 JSON 字符串形式的节点数组和节点内容。原始 echo、显式 source/trigger/batch 字段保留。同步模式和持久化模式共用这一步转译。

## 可选 AI 扩展

`submit_ai_task`、`get_ai_task`、`cancel_ai_task`、`send_ai_task` 与 `clear_ai_context` 为本工具自定义扩展，不属于 OneBot11 标准。它们沿用原连接与鉴权，由 RedReply 显式调用；任务 ID 不冒充消息回执，送达确认后才写短期上下文。配置、可导入示例与异步契约见 [AI.md](AI.md)。默认关闭，不修改其他平台接入或已有插件。

## 撤回边界

原版 RedReply 的 `输出流` 返回消息回执；`撤回` 会将指定回执转换为 `delete_msg`。原版电影插件把进度提示、搜索列表和图文详情分别登记撤回，游戏插件只撤回选择列表，正文可保留。适配器遵循这些回执边界。

例如同一输出的 `艾特 + 封面 + 详情 + 该消息2分钟后撤回` 可能在微信变成三条消息，但只返回一个输出 ID，撤回时逐条处理这三条。另一次输出的资源卡或正文不自动继承该计划。适配器对明确的“该消息 N 秒/分钟后撤回”和“施法中…请稍候”提示提前安排本次输出的撤回，避免业务脚本等待两分钟后才调用时已经超时；普通正文不会因此整批撤回。

来源消息 ID、`trigger_id` 或 `wechat_batch_id` 是追踪标记，不是输出回执。不能用一个来源 ID 代替全部输出 ID 来撤回；未知回执明确失败。尚未发送的延时任务不会因排队超过延时而被自动取消。主动取消该输出仍可阻止未开始的发送。

已核对的原生后端使用真实服务器消息编号撤回文字、图片和卡片，不依赖当前视口的菜单。每条仍按自己的发送时间限制在120秒内，同一输出优先撤回最早发出的部分；提交与确认分别持久化，未确认结果不会自动重试。微信4.2.0.12的真实回归中，临时提示在约24–27秒、三段图文在约98–102秒全部获得服务端撤回确认，无撤回计划的普通正文保持不变。历史超时消息不能补做超时撤回。未核对的原生版本保留界面路径及明确失败边界。

## 音乐播放

使用点歌插件已解析的 `audio` / `musicUrl`，保留原始协议和签名参数。发送前不带 Cookie 请求音频，拒绝登录页、JSON 错误和非音频响应；此检查不证明一定为完整曲目，也不能延长地址有效期。

原生卡片分别保留本次歌曲页面和音频地址，并在能核对当前QQ songmid时填写微信原生播放标识；不复制旧卡片的曲目标识，也不将歌曲页面替换为音频地址。GUI不再提供未经验证的点击模式切换，旧配置字段保留但不改变卡片生成方式。微信4.2.0.12上新建的QQ音乐卡已由接收端确认正常播放，此结果不代表所有曲目或音源均可播放。需要授权的音源仍需点歌插件提供有效、允许接收端播放的地址，适配器不会解除会员限制。原生发送回执与接收端实际播放是两项不同的验证。

## 明确不支持的动作

视频、文件发送，以及 QQ 的点赞、精华、管理员、禁言、表情回应等操作尚未实现。它们返回不支持，不会伪装成功或自动改成其他会话的动作。当前不支持将含非文字的历史输出仅按 ID 重建为转发节点；请传完整节点 content，避免图片被静默丢失。音乐、语音节点不能合并转发。

## 原生语音

`record.file` 支持 base64、HTTP(S) 和微信机器可读的绝对路径。远程 RedReply 的本地路径不能直接在另一台微信机器读取，应传 base64 或 HTTP(S)。静态内嵌解码器和 SILK 编码器支持 SILK、MP3、WAV、FLAC、AAC/M4A、Ogg/Vorbis；运行时不依赖 FFmpeg、Python 或外部编码器。

单条最长60秒，长音频按原顺序拆成多条原生语音，共用一次输出回执，最多接受10分钟/12MiB源文件。原生任务逐片上传并校验发送者、收件人、客户端标识、服务端状态和完整64位消息编号；不确定结果不自动重发。语音和音乐均按真实服务端回执记录，不伪造本机微信发件数据库。撤回仍遵守单次输出与120秒上限。

微信4.2.0.12已实测1秒原生语音气泡可播放，服务端确认和延迟30秒后撤回成功。其他微信版本需先核验后端，不能用音频文件冒充已支持。
